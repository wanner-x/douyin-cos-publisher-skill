# 抖音发布与编辑界面细则

仅在进入图文发布页或编辑已发布作品时读取本文件。

## 0. 客户端优先

- 默认使用已经登录的抖音桌面客户端。客户端中的创作者中心可能显示为第二个“抖音”窗口或内部浏览窗口；先枚举并选择包含 `creator.douyin.com` 的窗口，不要因为主窗口是推荐流就改去普通网页重新登录。
- 只有客户端确实缺少必要发布能力时才使用外部浏览器，并向用户说明切换原因。不得主动清除登录态或要求用户重复登录。
- 发布按钮索引、坐标和窗口顺序会变化；每次操作前重新读取当前界面，不复用旧索引。

## 1. 素材上传

- 优先上传原文件。如果 macOS 文件选择器无法可靠处理中文路径，可以在独立的 `/private/tmp` 目录创建按发布顺序编号的 ASCII 文件名副本，例如 `01-cover.jpg`、`02.jpg`；不要创建符号链接，也不要在此阶段移动原文件。
- 上传后核对图片数量、顺序和首图缩略图。临时副本不属于已发布归档素材。

## 2. 正文富文本

- 把作品描述视为富文本 `contenteditable`，不是普通输入框。
- 禁止在非空编辑器上用直接赋值替换正文；这可能追加内容、保留旧节点，或让编辑器与预览不一致。
- 替换内容时：聚焦编辑器 → `Cmd/Ctrl+A` → `Backspace` → 确认字数归零 → 输入正文 → 同时核对编辑器和发布预览。
- 标题与正文分开填写，不把标题、文件名或内部备注混入正文。
- 只有确认编辑器为空时，才可用直接赋值填写纯正文；之后仍必须做可见结果校验。

## 3. 话题实体

直接输入 `#话题` 只是普通文本，不能证明话题已经生效。每个话题都按以下步骤添加：

- 每条作品最多添加 5 个话题实体。内容属于二次元时，必须预留一个位置给 `二次元`；其余话题按相关性取舍，不能为保留旧方案而超过上限。

1. 将光标放到正文或上一个话题实体之后。
2. 点击 `#添加话题`，输入或粘贴搜索词。
3. 等候候选列表出现，点击与计划完全一致的候选项。
4. 确认候选列表关闭，话题在编辑器中成为独立实体或带样式节点；无障碍树中可能显示为带空格的 `# 话题`。

如果候选列表使用了正文、旧片段或错误搜索词，不要留下原始 `#文字`。删除当前未完成片段，必要时清空并重建正文，然后重新通过候选项添加。

所有话题添加后，预览必须同时显示完整正文和全部话题，编辑器中也要保留独立的话题实体。最终再次计数，最多 5 个；二次元内容必须包含已生效的 `二次元` 话题。只看到普通井号文本时，必须在提交前修正。

## 4. 发布、修改与事后核验

- 点击最终发布或提交修改前，再核对账户、素材数量与顺序、首图、标题、正文、话题实体、配乐、合集、可见性和定时设置。
- 修改已公开作品时，先记录页面显示的修改次数限制；一次提交可能消耗一次机会。必须在提交前取得用户确认。
- 发布前确认合集、公开范围和“立即发布/定时发布”状态；封面编辑后必须保存并回到发布页确认封面缩略图。
- 点击发布后只记录“已提交”，等待界面结果；禁止因为按钮仍可见或响应慢而再次点击。
- 到作品管理按准确标题查找本次作品，核对首图、图片数、发布时间和状态。搜索框可能是模糊匹配，必须以这四项共同锁定目标。
- 状态为“审核中”时保留原素材并等待；刷新后只有明确显示“已发布”才通过状态门槛。
- 再打开管理页或公开作品，分别确认正文存在，并且计划中的 5 个话题均可作为话题链接或实体识别。不能根据编辑器字数、预览或发布按钮跳转推断成功。
- 进入目标合集，记录总集数；按发布时间倒序查看作品列表，确认本批次位于最新一条且审核状态为“通过/已发布”。合集计数增加与最新作品匹配至少满足一项，最好两项都满足。
- 正文缺失、话题未生效或状态未知时，不自动重试或重复提交；报告现状并等待用户决定。
- 只有作品明确为“已发布”，且需要的合集归类也已核验，才允许执行用户授权的原素材归档。

## 5. 一次发布的证据清单

发布后至少保留下列可见证据，写入执行记录：

- 内容管理：准确标题、首图、图片数、发布时间、状态“已发布”；
- 成品内容：正文完整，5 个计划话题全部出现并可识别；
- 合集管理：合集名称、总集数变化或最新作品匹配、审核状态“通过/已发布”；
- 本地归档：精确原文件已从待发布目录消失，并完整出现在已发布目录。

若任一证据缺失，使用对应的中间状态，不要把整个流程报告为完成。
